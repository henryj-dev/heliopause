# 정책 평가를 별도 모듈 그래프로 옮긴다 — #89 와 realm 격리를 합친 설계

**상태**: 설계만. 구현은 이 문서가 머지된 뒤 사용자에게 다시 묻는다.
**합치는 근거**: #89(모듈 그래프 누출)의 1안과 realm 격리가 **같은 변경**이다. 따로 하면 두 번 한다.

**범위**: 이 문서는 **셋만** 담는다 — 측정(§1), 경계 결정(§2), 워커 생애주기 요건(§3). 대안은 §4
에 열린 채로 둔다.

⚠️ **이 문서는 한 번 더 길었고, 그 판이 블로커 여덟 건을 받았다**(P1 1 · P2 7). 블로커 대부분이
로직이 아니라 **문서가 만든 주장**에 있었다 — 닫힘 대조, 비용 해석, 롤아웃 주장. 이 저장소가
기록한 모양 그대로다: **틀이 커질 때마다 주장할 수 있는 것이 늘고, 그것을 검사하는 표면은 그만큼
자라지 않는다.** 그래서 줄였다. 넘긴 항목과 각각에 붙은 리뷰 지적은 **#117** 에 있다.

---

## 0. 한 줄

정책 모듈을 **평가마다 새 `worker_threads` 워커**에서 `import()` 하고, **추출과 직렬화까지 워커
안에서 끝낸 뒤** 결과를 `postMessage` 로 받고 **워커를 종료한다.** 모듈 그래프가 워커와 함께
사라지므로 누출이 끝난다.

## 1. 측정

### 1-a. 기존 두 수는 **서로 다른 측정**이었다

| 출처 | 수 | 무엇을 쟀는가 |
|---|---|---|
| #89 합성 | ≈0.28 MB/평가 | V8 `heapUsed`, 강제 GC 2회 뒤 |
| #89 운영 | ≈4.5 Mi/발행 | `kubectl top` = 컨테이너 working set, 평가 3회 |

4.5 Mi ÷ 3 ≈ **1.5 Mi/평가** 대 **0.28 MB/평가** 는 약 5배다. **#89 는 그 차이를 「`kubectl top`
이 heap 말고 컴파일된 모듈 코드 같은 V8 메모리까지 세기 때문」으로 제안하지만, 그 측정으로
세워지지는 않았다.** 그래서 아래 표는 heap 과 RSS 를 **같은 줄에** 적는다.

⚠️ 앞선 판은 「**#89 에 적혀 있지 않다**」라고 적었다. **적혀 있다** — 내가 읽은 줄이고, 그것을
축소했다. 과장을 피하려다 **원본을 줄인** 자리다.

### 1-b. 로컬 — 픽스처 **A**

**기준**: node 26.4.0 · darwin 25.6.0 · `--expose-gc` · 각 표본은 **강제 GC 2회 + macrotask
yield** 뒤 `process.memoryUsage()` · 평가 **60회** · 2026-10-06.

**픽스처 A 의 모양**: `policies.json` **0.19 MB**(객체 540행, 각 행에 문자열 넷·배열 둘) ·
사이트 모듈 **0.13 MB**(`const` 선언 1,080개 + 그 JSON 을 `import`).

| 조건 | heapUsed/평가 | rss/평가 |
|---|---|---|
| 지금 (자식까지 버전 — #59·#63) | **+0.556 MB** | **+0.626 MB** |
| 자식 버전 훅 OFF (#59 이전 동작) | **+0.343 MB** | +0.346 MB |
| 평가마다 워커, 종료 | **+0.016 MB** | 1-e |

10회마다 표본을 떠서 **선형**이다. 평가가 멈추면 늘지 않고 **줄지도 않는다.**

### 1-c. 로컬 — 픽스처 **B** (같은 표에 섞지 않는다)

**픽스처 B 의 모양**: `policies.json` **0.32 MB**(객체 900행) · 사이트 모듈 **0.08 MB**(`const`
700개). 기준은 1-b 와 같다.

| 조건 | heapUsed/평가 |
|---|---|
| 지금 | **+0.582 MB** |
| 자식 버전 훅 OFF | **+0.229 MB** |

🔑 **A 와 B 를 나눠 적는 이유**: 앞선 판이 **A 의 수와 B 의 수를 한 절에 섞어** 「훅이 2.5배」라고
적었다(그 2.5배는 **B** 의 비, A 는 1.62배다). 픽스처가 다르면 **다른 실험**이고, 비율도 함께
움직인다.

### 1-d. 🔴 #89 의 합성 수는 **재현되지 않았다**

```
#89        0.13 → 0.28  MB/평가   (2.15배)
픽스처 A   0.343 → 0.556 MB/평가  (1.62배)
```

**#89 가 적은 바이트 크기에 맞췄는데도** 2배 차이다.

**가릴 수 없다**: #89 는 픽스처의 **크기만 적고 모양을 적지 않았다.** 바이트 수는 보존되는 heap
을 결정하지 않는다 — 큰 배열 하나와 객체 리터럴 1,080개는 다르게 남는다. ⚠️ 그것이 **차이의
원인이라고는 적지 않는다**(앞선 판은 그렇게 적었다). **왜 다른지 세울 방법이 없다**는 것까지가
세워진 것이다.

→ 재현된 것은 **모양**(선형 · 회수 없음 · 훅이 증폭)이고 **크기는 아니다.** 그래서 이 문서는
자기 픽스처의 **모양**을 §1-b·§1-c 에 적는다.

### 1-e. 워커의 RSS — 한 번 틀리게 적었다

처음 「워커도 RSS +0.543 MB/평가」로 적었다. N 을 바꾸면:

| N | 총 증가 | 「평가당」 |
|---|---|---|
| 15 | +5.34 MB | +0.356 MB |
| 30 | **−5.08 MB** | −0.169 MB |
| 60 | **−1.63 MB** | −0.027 MB |

120회에서는 끝 표본이 10회 때보다 낮았다(63.23 대 64.63 MB).

→ **이 실행들에서 지속적인 RSS 증가는 관측되지 않았다.** ⚠️ 「늘지 않는다」고는 적지 않는다
(앞선 판은 그렇게 적었다). 음수와 N 에 반비례하는 「평가당」 값은 **일회성 비용을 N 으로 나눈
모양과 일치**하지만, **그 설명이 측정된 것은 아니다.**

### 1-f. 운영 대조 — 평가 없으면 평평하다

**기준**: `kubectl top pod --containers` 의 render 컨테이너 working set, 15분 간격. 평가 수는
render 로그의 `evaluated` 줄 누계. **heliopause-ba 측정**, 원본
`/private/tmp/claude-501/audit-d35372c2/render-memory.tsv`(10-05 07:06~14:08Z 행은 무효 표시).

| 관측 | 값 |
|---|---|
| 평가 없는 구간 | 파드 `n7mf4` 약 **71시간** 35~36 Mi · 파드 `2drcp` 약 **9시간** 30~31 Mi |
| 계단 | +3평가 → **+4~5 Mi** · +3평가 → **≈0** · +4평가 → **+3~4 Mi** |
| 누적을 지운 것 | **롤아웃(파드 교체)만** — 39 → 30 Mi |

⚠️ **그 쪽이 명시한 한계**: `≈0` 계단이 GC 회수인지 **1 Mi 해상도에 묻힌 것인지 가를 수 없다.**
계단은 **발행 수가 아니라 평가 수**를 따른다. 표본 사이 공백이 셋.

🔑 로컬 `+0.626 MB/평가`(픽스처 A, RSS)와 운영 `≈1~1.5 Mi/평가` 는 **같은 자릿수다. 같다고는
적지 않는다** — **로컬 RSS 와 컨테이너 working set 은 다른 대상**이다.

### 1-g. 원인 — ESM 레지스트리이고, 자식 버전 훅은 **증폭기**다

`import("<site>?v=<stamp>")`(`bin/heliopause-policy-render.ts:819`)의 URL 이 스탬프마다 바뀐다.
**ES 모듈은 URL 로 캐시되고, 프로세스가 항목을 지울 수 없다.**

| 대조군 | 결과 | 무엇을 배제하는가 |
|---|---|---|
| 결과를 **아예 버린다**(`held = null`) | 수가 **동일**(소수점까지) | **명시적으로 들고 있던 export** 가 원인이 아니다. ⚠️ 「이 프로세스가 들고 있는 것이 아니다」라고는 적지 않는다 — **ESM 레지스트리도 이 프로세스 안**이다 |
| 자식 버전 훅 **OFF** | 줄지만 **0 이 아니다** | 훅(`:486`)은 **원인이 아니라 증폭기**다. entry 모듈만 버전해도 레코드가 남는다 |

`cached.set(sitePath, …)`(`:893`)은 슬롯 하나이고 이전 `source` 는 풀린다.

ℓ **Node 에 레코드를 evict 하는 공개 API 를 나는 모른다.** 「없다」고 적지 않는다 — 찾아본 범위가
그만큼이다.

### 1-h. 비용

**기준**: 타임드 루프 **안에 GC 없음**, 첫 회를 따로 적음, 20회 평균, node 26.4.0.
**측정한 것은 `import()` 와 작은 응답 하나의 왕복이다** — **완전한 `PolicySource` 를 만들고
복제하는 비용은 재지 않았다**(§2 가 그것을 워커로 옮기므로 구현 때 다시 재야 한다).

```
워커        첫 41.7 ms · 그 뒤 17.9 ms/평가
인프로세스  첫  2.2 ms · 그 뒤  1.7 ms/평가
```

⚠️ 이 수가 **어느 요청 경로에 어떻게 붙는지는 이 문서가 주장하지 않는다.** 평가는 **기동**,
**`/readyz`**, **`/source`** 세 자리에서 일어나고, 앞선 판이 「요청이 올 때만」·「기동은 직렬
합계」라고 적어 둘 다 틀렸다. → **#117**.

## 2. 경계 — **추출과 직렬화는 워커 쪽 필수**

| 일 | 어디서 | 왜 |
|---|---|---|
| `import()` 와 사이트 모듈 평가 | **워커** | 이 설계의 전부 |
| `collectPolicySource`(`resolveService` 호출 + `toWire`) | **워커 (필수)** | 아래 |
| 스탬프(`sourceStamp`) | 부모 | 디스크를 읽을 뿐 모듈을 평가하지 않는다 |

### 왜 **필수**인가 — 함수 값은 추출 **뒤에만** 사라진다

```
src/policy-source.ts:365   const hit = resolver(ref);                              ← resolveService 호출
src/policy-source.ts:376   if (hit) services[ref] = toWire(hit) as ServiceSelector;
src/policy-source.ts:409   const wire = toWire({ ...site, resolveService: undefined }) as ScreenSite;
```

### 불변식은 **어디서부터 참인가**

| 자리 | 그 시점의 값 | 클론 가능한가 |
|---|---|---|
| `src/policy-source.ts:365` **전** — 원시 `site` | `resolveService` **함수**를 들고 있다 | ❌ |
| `:376` · `:409` **후** — `site` 와 `services` | `toWire`(JSON 왕복, `:53-54` 의 캡처된 `parseJson`/`writeJson`)를 지났다 | ✅ |
| `:437` — `repo.probes` | `readCoverageProbes` 가 **그대로** 넣는다. **`toWire` 를 지나지 않는다** | ❌ **보장 없음** |

🔴 **그래서 「`PolicySource` 에는 JSON 으로 표현되는 값만 남는다」는 거짓이다.** `toWire` 는
**`site` 와 resolver 결과만** 덮고, 완전한 source 는 **그 뒤에 조립된다.** `repo.probes` 는
`src/policy-screen.ts:146` 의 **캡처되지 않은 `JSON.parse`** 가 돌려준 것을 직렬화 없이 싣는다 —
독립 리뷰가 그 파서를 함수를 품은 probe 를 돌려주는 것으로 갈아치우니 `collectPolicySource` 는
**성공하고** 그다음 `structuredClone(source)` 이 **`DataCloneError`** 로 던졌다.

⚠️ 같은 문장을 **두 번 연속 한 방향으로만 참**이게 적었다. 처음엔 「함수 값은 이미 넘지 않는다」
(P1 블로커), 고치면서 「`:409` 이후에만 참」 — **그 뒤에 또 조립되는 자리를 못 봤다.**

### 요건

1. **워커가 나가는 `PolicySource` 전체를 자기 안에서 직렬화한다 — `repo.probes` 를 포함해서.**
   부모는 **직렬화된 바이트만** 받는다. 「어디까지 `toWire` 를 지났는가」를 따지는 설계는 위 표가
   보여준 자리에서 또 틀린다.
2. **직렬화나 클론이 실패하면 그 사이트의 실패로 처리한다**(503). 워커를 종료하고, 캐시에 넣지
   않는다.

ℓ **실제 `PolicySource` 를 워커로 보내 보지 않았다.** 근거는 위 표의 코드 줄과 리뷰의 프로브다.
**구현의 첫 작업이 그것을 보내는 테스트**여야 한다.

### 존 검사의 자리는 정하지 않는다

`zoneMismatch` 를 부모에 두면 **와이어 데이터**를 검사하므로 모듈이 위조할 수 없고, 워커에 두면
한 번에 끝난다. **정하지 않았다** → **#117**.

## 3. 워커 생애주기 요건

평가 하나는 **반드시 정확히 한 번 결말**이 나야 하고, **모든 결말에서 워커가 종료**돼야 한다.
그러지 않으면 이 설계가 고치려는 누출이 **스레드 누출로 바뀐다.**

| 결말 | 무엇이 와야 하는가 | 요건 |
|---|---|---|
| 정상 | **전용 채널**의 메시지가 **스키마를 통과** | 결과를 받고 **종료한다**. ⚠️ 「`message` 가 왔다」는 정상이 **아니다** — 요건 2 |
| 모듈이 throw | `error` | **핸들러를 반드시 단다** — 없으면 부모의 uncaught exception 이 된다 |
| 직렬화 실패 | `error` | 종료하고, 그 사이트만 503 |
| **`process.exit(0)`** | **아무것도 안 온다** | 🔴 `exit` 이벤트로만 알 수 있다. 모듈이 이것을 부를 수 있다 |
| 평가 타임아웃 | 아무것도 안 온다 | 부모 타이머가 `terminate()` 한다 |
| 동기 spin | 아무것도 안 온다 | 같음 |

### 반드시 적어 둘 것

1. **`exit` 를 결말로 센다.** `message` 도 `error` 도 없이 끝나는 길이 있다 — 모듈의
   `process.exit(0)` 이 그렇다. **세 이벤트(`message`·`error`·`exit`) 모두에서** 평가가 결말나야
   한다.

   🔴 **「먼저 온 것이 이긴다」는 쓰면 안 된다 — 앞선 판이 그렇게 적었고, 그것이 공격면이었다.**
   정책 모듈은 **`parentPort` 를 직접 import 해서** 평가기보다 먼저 답할 수 있다. 재현:

   ```
     message: {"hosts":[{"id":"forged.by-the-module","stage":"gateway"}]}
     error: the real evaluation then failed
     exit: 1
   ```

   **위조가 먼저 도착한다.** 「먼저 온 것이 이긴다」 + 「`message` = 정상」이면 부모가 **위조를
   받고 실제 실패를 버린다.** 생애주기 규칙을 쓰라는 지적을 받아 쓴 규칙이 **새 구멍을 만들었다.**
2. 🔴 **워커 메시지는 신뢰할 수 없는 입력이다.** 메시지를 받은 것은 **추출이 끝났다는 증거가
   아니다.** 그래서 셋이 필요하다:

   - **부모가 스키마로 검증한다.** 형식에 안 맞는 응답은 **받기 전에** 그 사이트의 실패로.
   - **결과는 평가기만 아는 채널로만 받는다.** 모듈이 `parentPort` 로 보내는 것은 부모가 **결과로
     세지 않는다**(막을 수는 없다 — 모듈이 그것을 import 할 수 있다).
   - **그 채널을 `workerData` 로 넘기면 안 되고, 평가기가 `import` 보다 먼저 받아야 한다.** 측정이
     그 둘을 정했다(아래).

   ### 측정 — 전용 포트가 **무엇을 막고 무엇을 못 막는가**

   **기준**: node 26.4.0, 부모가 `MessageChannel` 을 만들어 워커에 넘기고, 모듈이 세 방향으로
   답하려 시도한다. 2026-10-06.

   | 포트를 넘기는 방법 | 위조가 전용 포트에 도착하는가 |
   |---|---|
   | **`workerData` 에 넣는다** | 🔴 **도착한다** — 모듈이 `workerData.reply` 를 **읽어서** 보낸다 |
   | **초기 `postMessage` 로 넘기고, 평가기가 `import` 전에 받는다** | **도착하지 않는다** |
   | 초기 메시지로 넘기지만 **평가기가 `import` 를 먼저** 한다 | 🔴 **도착한다** — 모듈이 `parentPort.once("message")` 로 **포트를 훔치고**, 평가기는 포트를 잃는다 |

   → **순서가 요건이다.** 전용 채널을 쓰는 것만으로는 부족하다.

   ### 못 막는 것 · 재지 않은 것

## 4. 대안 — `vm` 은 **열린 선택지**다

| | 동기 spin | 메모 |
