# az01-icn-own 인수 — heliopause 쪽 절차

홈랩 3대(`gw-01` Pi · `k3s-01` · `storage-01`)를 heliopause 관리로 넘기는 절차. 전체 계획은
stardust 런북 §0·§10(`11e86b7b`)이 정본이고, 이 문서는 **heliopause 가 하는 부분**만 적는다.
운영 변경은 포함하지 않는다 — 읽고 결정하기 위한 문서다.

작성 2026-10-05. 아래 「측정」은 전부 이 저장소 `main`(`8c94f36` 기준)에 대고 잰 것이다.

## 0. 먼저: 코드 변경이 필요한가 — **아니다**

세 가지를 재서 확인했다.

| 물은 것 | 측정 | 뜻 |
|---|---|---|
| 사이트·존 이름이 코드에 박혀 있나 | `grep -rn "dev-icn-own\|az01" src/ bin/ agent/` → **0 건** | 개명은 **정책 저장소와 환경변수** 일이다 |
| `10.113` 이 코드에 있나 | `grep -rn "10\.113" src/ bin/ agent/` → **0 건** | 같다 |
| 렌더러가 사이트 넷을 볼 수 있나 | `HELIOPAUSE_POLICY_SITES` 가 `bin/heliopause-policy-render.ts:404` 에 **구현돼 있다** | 네 번째 사이트는 **설정 한 줄**이다 |

→ **에이전트도 렌더러도 바꿀 것이 없다.** 이 인수는 정책·설정·절차이고 PR 이 필요한 코드
변경은 지금 보이지 않는다.

⚠️ 이 세션의 기록에는 멀티사이트가 **미구현**으로 적혀 있었다. 그것은 낡은 메모였고,
`HELIOPAUSE_POLICY_SITES` 는 이미 있다. 이 문서를 읽는 사람도 그 메모를 만날 수 있으니
여기에 적어 둔다.

## 1. 개명 — 10.113 → 10.112 가 heliopause 에서 바꾸는 것

`112 + (AZ-1)` 공식에 따라 az01 은 **10.112** 다. 10.113 은 az02 의 것이 된다.

| 바꿀 것 | 어디 | 상태 |
|---|---|---|
| 사이트 이름 | 정책 저장소의 사이트 모듈 파일명·`site.name` | `az01-icn-own` |
| 존 이름 넷 | 같은 파일의 `ZONES` | `own-*` → az01 명명 규칙에 맞출지 **결정 필요**(§5) |
| CIDR 넷 | 같은 곳 | `10.112.0.0/16` · `/17` · `.192.0/18` · `.128.0/18` |
| 라우트 선언 | 사이트의 `routes` | `10.112.0.0/16 dev wg0 owner: wireguard` |
| 테스트 픽스처 | `dev-routes.test.ts` 의 wg0 행, 손수 소유 라우트 수 6→7 | |

| stardust 쪽 `PEER_CIDR` | `add-peer-vpc.sh` 인자 | **다른 저장소** — 알려야 한다 |

### stash 157줄 — 적용하지 않고 다시 쓴다

공유 stash `stash@{0}` `f555322` 에 네 zone 과 라우트 선언이 있다. **적용하지 않는다**:
주소가 전부 10.113 시절이고, 주석에 **2026-09-28 에 실제로 측정한 값들**이 담겨 있다
(`10.113.70.122` DHCP 리스 없는 ARP 항목 · `10.113.94.168` KT 라우터 관리 IF ·
MinIO `10.113.0.11:9000`). 주소만 바꿔 적으면 **측정하지 않은 값을 측정값으로 적는 것**이
된다.

가져올 것은 **논증**이다 — 왜 zone 이 넷인지(`zoneOf` 가 최장 일치를 쓰므로 `/16` 하나면
홈랩 pod 가 VPC trust 로 올라간다), 왜 `trust: 2` 인지(소유는 「빼앗기지 않음」이고
「들어올 수 없음」이 아니다 · Pi 가 오피스 LAN 과의 유일한 경계 · 물리 콘솔 개방 + PXE 무인
설치 · Rocky 9.8 은 함대 표준 밖이고 heliopause 의 측정 집합 밖), 왜 `/17` 인지(`/18` 은
`.63.255` 에서 끊겨 브리지 모드 KT 라우터의 관리 인터페이스를 빠뜨린다 — 2026-08-10 에
dev 의 nodeNet 을 `/17` 로 만든 그 실패 모양), 왜 라우트 owner 가 `wireguard` 인지(복구가
`add-peer-vpc.sh` 를 다시 돌리는 것이고 wg-quick 이 라우트를 깐다. `provisioning` 으로 적으면
**한 명령 복구가 조사로 바뀐다**).

주소와 측정값은 **재측정**한다. prod·util 의 `10.113` 라우트 선언도 같은 조건에 묶여 있다.

## 2. enroll 순서

3대 모두 **재설치 뒤**다. 메시 정적 경로(5개 /16, `lan0`, `never-default`)가 **공인 링크보다
먼저**다 — stardust §0 9-c.

1. **`k3s-01`** · 2. **`storage-01`** — 둘은 공인에서 받을 것이 없다. 먼저 넣어 함대 모양
   (기본 drop + 출처 묶인 관리 SSH)을 확인한다.
3. **`gw-01`(Pi)** 마지막. 그 호스트가 **지금 세 대의 유일한 경계**이므로, 그것을 넘기는 순간
   잘못되면 세 대가 함께 노출된다. 둘이 자기 방화벽을 들고 있는 뒤에 넘긴다.

각 호스트는 **enroll → 첫 세대 발행 → confirm** 까지가 한 단위다. 인가는 **호스트마다 따로**
발급된다(`heliopause-pull.py:3952` 가 `target` 과 `host` 를 둘 다 검사) — 한 번 발행하면
서명 페이로드가 **호스트 수만큼** 나온다.

## 3. 방화벽 모양 (사용자 결정, 재구축 후 값)

`k3s-01` · `storage-01`:

- **`lan0`**(내부·온보드, MAC 고정): established/related, icmp, **`ip saddr 10.112.0.0/16` 전체
  허용** — 포트를 나열하지 않는다. 파드 `10.112.128.0/18` 과 서비스 `10.112.192.0/18` 가 그
  안이고, Cilium native routing 이라 VXLAN 이 필요 없다.
- **`wan0`**(공인·USB, MAC 고정): established/related **만**. **22 포함 인바운드 전부 drop.**
  원격 관리는 `lan0` 과 메시로만.
- 정책이 인터페이스 이름을 참조하면 **`lan0`/`wan0`** 를 써야 한다.

`gw-01`(Pi): 자체 `gw_base`(input policy drop)로 돌고 있고, **`eth1:22` 가 출처 무제한**이다.
인수 때 고친다(사용자 결정).

### IPv6 — 별도 체인이 필요하지 않다

stardust 가 「두 호스트에 ip6 base INPUT 체인이 아예 없다」고 보고했다. 그것은 **현재**
상태이고, heliopause 가 넘겨받으면 해소된다: 이 저장소의 테이블은
**`TABLE_FAMILY = "inet"`**(`heliopause-pull.py:177`, `src/nft-json.ts:146`)이고 `inet` 은
**v4·v6 를 한 테이블이 덮는다**. 렌더러는 `ip6 saddr` 룰을 같은 테이블 안에 낸다
(`src/nft.ts:540`). Cilium 이 `enable-ipv6=false` 인 것과 무관하게 **기본 drop 이 v6 에도
걸린다.**

→ 따로 ip6 체인을 만들 필요가 없다. **확인할 것**은 인수 뒤 `nft list table inet heliopause`
에 v6 기본 drop 이 실제로 보이는지다.

## 4. 재부팅 뒤 복원 — 수단은 heliopause 자신이다

두 호스트는 **firewalld masked, nftables disabled** 라 지금은 재부팅 때 복원할 장치가 없다.
인수 뒤에는 **에이전트가 그 수단**이다:

- 재부팅은 `table inet heliopause` 를 지운다(커널 메모리).
- 다음 하트비트에서 `handle_reply` 가 **상태는 `confirmed` 인데 테이블이 없는 것**을 보고
  **다시 적용한다**(`heliopause-pull.py:5075`, 「confirmed but the table is absent — re-applying」).
  이 경로는 테스트로 고정돼 있다(`TestTheExpiryEscapeOnAStateThatWasRun`).
- 만료된 인가도 그 호스트가 그 세대에 대해 `confirmed` 이면 **탈출로로 다시 적용된다**
  (`:4375`). 그 탈출로는 함대에 이미 배포돼 있다.

⚠️ **그래서 복원은 「릴레이에 닿을 수 있을 때」까지다.** 릴레이가 안 닿는 동안 재부팅하면
**필터가 0** 이고, 에이전트가 가져올 수 있을 때까지 그 상태다. 이것은 알려진 한계이고 별건
으로 추적된다. Pi 가 경계인 구성에서 **Pi 를 마지막에 넘기는 이유**도 이것이다.

nftables 유닛을 켜서 디스크의 룰을 부팅에 복원하는 방식은 **쓰지 않는다** — 디스크의 사본이
heliopause 가 보낸 세대와 갈라지면 「확인된 세대」가 두 뜻을 갖게 된다. 그 선택은 §5 에 결정
항목으로 올린다.

## 5. 사용자 결정이 필요한 것

1. **존·사이트 이름**: `own-vpc`/`own-nodes`/`own-services`/`own-pods` 를 그대로 둘지,
   `az01-*` 명명으로 바꿀지. 바꾸면 stash 재작성과 한 번에 끝나고, 두면 기존 문서·링크가 산다.
2. **부팅 복원 수단**: 위 §4 대로 **에이전트만**(릴레이 의존)인지, 아니면 nftables 유닛으로
   디스크 사본도 둘지. 후자는 「두 뜻」 위험을 들인다.
3. **Pi 인수 시점**: 두 서버 뒤라는 순서는 정해졌고, `eth1:22` 를 **인수와 같은 창에서**
   고칠지 분리할지.
4. **첫 발행 범위**: 3대를 한 세대로 발행할지 호스트별로 나눌지. 인가는 호스트마다 따로
   발급되므로 한 세대로도 되지만, 되돌릴 때의 단위가 달라진다.
